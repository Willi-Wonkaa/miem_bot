# Частичная индексация

`index-data/checkpoints/` — чанки, батчи `.npy` и готовые векторы каждого файла.
Ключ: содержимое файла, метаданные, модель/точность и версия алгоритма.
После сбоя повторный запуск пересчитывает только отсутствующие батчи; неизменённые файлы переиспользуются.

DOCX/TXT/PDF разбираются параллельно, без копирования модели в процессы парсинга.
Короткие документы идут первыми. E5 — один многопоточный процесс, CPU INT8 по умолчанию.
Модель одна и та же у RAG и индексатора; менять `EMBED_QUANTIZE` нужно вместе с пересчётом базы.

Первый файл сразу создаёт рабочий индекс. Следующие версии публикуются каждые `INDEX_PUBLISH_PERCENT=5`%.
Каждая версия содержит согласованные FAISS, чанки, ссылки, FAQ и метаданные.
`CURRENT` меняется атомарно после записи всех артефактов. Статические FAQ/ссылки используют hard links.
RAG загружает новую версию в фоне и меняет ссылку на неё; выполняющиеся запросы используют старую копию.

До первого файла API и бот доступны, отвечают о подготовке базы. На частичной базе ответ показывает
сколько файлов доступно и последние имена. `/index_watch` включает отдельные отбивки о файлах.
Служебный бот показывает файлы, процент, текущие чанки, прошедшее время и примерный ETA.
ETA уточняется по мере разбора документов и изменения скорости CPU.

На 3 CPU / 8 GiB по умолчанию индексатор ограничен 1.6 CPU / 3 GiB, низкий CPU weight.
Монитор оставляет минимум 1 CPU / 3 GiB для остальных процессов и отдаёт до 80% остатка.
Если рабочий набор уже не помещается в безопасный бюджет, запрашивается остановка с сохранением прогресса.
Запуск и возобновление: Actions → Run workflow → `index`; deployment token `SERVICE_BOT_TOKEN` обязателен.
