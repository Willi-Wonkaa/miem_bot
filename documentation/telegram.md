# Основной Telegram-бот

Точка входа — `app/telegram/bot.py`, контейнер `bot`. Бот получает сообщения через long polling, вызывает внутренний RAG API и отправляет ответ пользователю. Для запуска нужны `TELEGRAM_BOT_TOKEN`, `RAG_API_TOKEN`, Redis и работающий `rag`.

| Файл | Что делает |
| --- | --- |
| `bot.py` | Команды, проверка текста, вызов `/answer`, отправка ответа, heartbeat |
| `history.py` | История Redis и блокировка одновременных запросов на одну сессию |
| `formatting.py` | HTML-экранирование и разбиение длинного ответа для Telegram |
| `archive.py` | Запись входящих/исходящих сообщений в SQLite |
| `feedback.py` | Кнопки «Помог ответ» / «Не помог», комментарий |
| `../transcripts.py` | Таблицы и запросы SQLite-архива |

Команды: `/start`, `/reset` (очистка контекста Redis), `/index` (состояние базы), `/index_watch` и `/index_unwatch` (уведомления о новых файлах). Обычный текст передаётся в `POST /answer`. Нетекстовое сообщение получает отдельный ответ. Бот передаёт до десяти записей истории; `HistoryStore` оставляет пять пар и обновляет TTL, по умолчанию 24 часа.

Сейчас бот записывает вопросы, ответы, вложения и оценки в `CONVERSATION_DIR/conversations.sqlite3`. Кнопки оценки живут десять минут; отрицательная оценка запрашивает комментарий. Это отдельный долговременный архив: `/reset` очищает только Redis-контекст. Служебный бот читает тот же архив через `app/service/history.py`; просмотр и экспорт ограничены списком `SERVICE_ADMIN_IDS`.

Compose передаёт обоим ботам `CONVERSATION_DIR=/data/history` и монтирует общий каталог для записи. На VPS он связан с `/opt/miem-bot/shared/history/`; серверный скрипт выставляет права для UID 10001. Для просмотра переписок задайте `SERVICE_ADMIN_IDS` в серверном `.env` JSON-массивом Telegram ID, например `[123456789]`. Формат архива и команд — в [отдельной странице](history.md).
