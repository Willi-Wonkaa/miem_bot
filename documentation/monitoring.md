# Логи и служебный бот

`SERVICE_BOT_TOKEN` — токен отдельного бота в серверном `shared/.env`.
Каждый администратор активирует его через `/start` в личном чате. Белого списка нет.
Кнопки: статус; все уведомления; запуск компонентов; статистика; индексация; готовые файлы; ошибки.
Настройки независимы для каждого чата и сохраняются после рестарта.

Сообщения считаются за 1/5/30 минут и с последнего запуска основного бота.
Статистика отправляется раз в минуту (`SERVICE_REPORT_SECONDS`).
Статус показывает Docker state/health, время старта, компоненты и прогресс индексатора.

Логи UTF-8: `/opt/miem-bot/shared/logs/*.txt`; ротация по 10 MiB, 5 резервных файлов.
`indexer.txt`, `bot.txt`, `rag.txt`, `service.txt`, `host-monitor.txt`.
Логируются этапы, длительность, ошибки, файлы и расход токенов LLM; ключи маскируются.
Тексты вопросов/ответов и история целиком в логи не записываются.

`monitor-data` — SQLite: события, счётчики, подписки и настройки кнопок.
`miem-monitor.service` на VPS собирает состояния Docker и меняет лимиты индексатора.
У контейнеров нет Docker socket. Установка: `sudo bash scripts/install_monitor.sh /opt/miem-bot/pending`.
Резерв: минимум 1 CPU и 3 GiB RAM для ОС и остальных процессов; индексатору — до 80% остатка.
При нехватке RAM запрашивается остановка, чтобы не уменьшать лимит ниже рабочего набора памяти.

Порядок старта: `service` → `redis`/`rag` → `bot`; индексатор тоже ждёт готовности `service`.
Команды основного бота: `/index`, `/index_watch`, `/index_unwatch`, `/reset`.
Эта версия сохраняет полный индекс после завершения расчёта; частичная публикация будет в следующей версии.
