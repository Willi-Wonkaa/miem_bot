# RAG API и выдача ответа

Точка входа — `app/rag/api.py`, контейнер `rag`. Uvicorn слушает порт 8000 только внутри сети Compose. `RAG_API_TOKEN` защищает пользовательские маршруты; `POLZA_API_KEY` нужен для генерации.

| Маршрут | Назначение |
| --- | --- |
| `GET /health` | Состояние процесса и `index_ready` |
| `GET /index` | Покрытие базы и текущий прогресс; Bearer-токен |
| `POST /answer` | Вопрос, до 10 строк истории; Bearer-токен |

Вопрос ограничен 4000 символами. По умолчанию API обрабатывает два запроса одновременно; после пяти секунд ожидания возвращает 429. Ошибка генерации становится 502. Ответ содержит `answer`, `sources`, `route`, `tokens`, `time_sec`, `coverage`. Также возвращаются `answered_at` и `model` для архива диалогов.

## Маршруты ответа

- `fallback`: опубликованного индекса нет. Polza отвечает без документов и без источников.
- `faq`: `Retriever.prepared_answer` находит готовый русский ответ из Excel. LLM не вызывается.
- `rag`: поиск по документам, rerank и ответ Polza. Английский вопрос сразу проходит этим путём, поскольку FAQ русскоязычный.

`app/rag/retrieval.py` объединяет до 60 кандидатов FAISS и 60 BM25 через RRF, затем передаёт до 40 в `Pipeline`. `pipeline.py` при наличии истории переписывает вопрос, ранжирует кандидатов через Polza, собирает контекст из документов и соседних фрагментов, выбирает подходящие ссылки и генерирует ответ. Тексты промптов — в `prompts.py`. Названия использованных документов возвращаются в `sources`.

`app/rag/live_index.py` следит за файлом `CURRENT` в volume `index-data`. Новое поколение загружается целиком в фоне; запрос, который уже начался, продолжает использовать старый snapshot. Если новая публикация повреждена, предыдущая остаётся доступной. Модель E5 загружается при первой загрузке индекса; `model-cache` хранит скачанные файлы модели.

Проверка из контейнера: `python -m app.rag.smoke`. Флаг `--require-index` требует хотя бы один доступный документ, `--require-complete` — полное поколение, `--question` вызывает реальный ответ и Polza API.
