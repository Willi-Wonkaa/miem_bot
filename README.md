# MIEM Bot

Telegram-ассистент НИУ ВШЭ: готовые ответы из Excel и ответы по документам с помощью RAG.
Python 3.12, Docker Compose, GitHub Actions; модель эмбеддингов работает на CPU.

## Запуск всей системы одной командой

Через GitHub CLI, без локального запуска приложения:

```bash
gh workflow run ci-cd.yml --ref main -f mode=index
```

Из корня репозитория также доступен лёгкий клиент с отслеживанием результата:

```bash
python scripts/start.py
```

Команда запускает GitHub Actions в режиме `index`: проверки кода → сборка → доставка
проверенного commit на VPS → служебный бот → монитор ресурсов → Redis/RAG → основной бот
→ возобновляемая индексация. В консоли появляется ссылка на конкретный запуск.
Команда ждёт результат и возвращает ошибку, если CI, deploy или проверка системы не прошли.
В `index` успешный старт означает: корпус проанализирован, каждый рабочий индексатор
обработал хотя бы один документ, и база доступна для ответов. После этого Actions заканчивается;
индексация продолжает работать на VPS в фоне. Полную готовность проверяет служебный бот.
Пропущенный deploy тоже считается ошибкой, даже если GitHub обозначил весь workflow успешным.

Нужны Python 3.12, доступ к репозиторию и GitHub-аутентификация в Git
(Git Credential Manager) либо переменная `GH_TOKEN`/`GITHUB_TOKEN` с правами запуска Actions.
Дополнительные Python-пакеты и локальный Docker для этой команды не нужны.
Она разворачивает **опубликованную ветку `main`**; локальные изменения сначала нужно
закоммитить и отправить в GitHub. Локальный `.env` на VPS не загружается.

Другие режимы:

```bash
python scripts/start.py --mode deploy   # запустить/обновить сервисы без индексации
python scripts/start.py --mode prepare # доставить исходники и собрать образы
python scripts/start.py --no-wait       # запустить index, напечатать ссылку и выйти
```

Остановка ожидания через Ctrl+C не отменяет workflow и серверную индексацию.
Вместо команды можно открыть [CI and deploy](https://github.com/Willi-Wonkaa/miem_bot/actions/workflows/ci-cd.yml)
→ Run workflow → `main` → `index`. Каждый push в `main` автоматически проходит CI
и запускает deploy в режиме `index`. После merge PR в `main` система обновляется сама.
PR и другие ветки проверяются без изменения production. Переменная `DEPLOY_ENABLED` не требуется.

## Подготовка перед первым запуском

1. Подготовить Ubuntu VPS и SSH-доступ через `scripts/bootstrap.sh`; добавить SSH-секреты
   в Actions и создать environment `production`. Подробности — [CI/CD](documentation/ci-cd.md).
2. На сервере скопировать `.env.example` в `/opt/miem-bot/shared/.env`, установить права `600`
   и заполнить `TELEGRAM_BOT_TOKEN`, **отдельный** `SERVICE_BOT_TOKEN`, `POLZA_API_KEY`,
   `RAG_API_TOKEN`. Для внутреннего токена подходит
   `python -c "import secrets; print(secrets.token_urlsafe(32))"`.
3. Архив `MIEM_knowledge_base_unified.zip` и Excel `HSE_Answers_RU.xlsx` уже находятся
   в `data/raw/`: deployment копирует их на сервер. При замене данных добавить новые файлы
   туда либо в серверный `shared/raw/`. Импорт из исходного каталога:
   `python scripts/import_data.py ..`.
4. Выполнить `python scripts/start.py`. В служебном боте отправить `/start`, чтобы
   подписаться на уведомления; в основном боте можно проверить `/index` и задать вопрос.

Токены не коммитятся и не попадают в образы. Для запуска нужны значения из **серверного**
`shared/.env`, а не только из локальной копии.

## Как база становится доступной

Служебный бот запускается первым. Основной бот и HTTP API могут работать с пустым индексом:
до публикации документов генератор отвечает без материалов базы и не придумывает источники.
При частичной базе ответ проходит через доступные документы. Отдельным сообщением бот
предупреждает: «Ответ может быть неполным: база знаний сейчас обновляется».
Числа обработанных файлов и их имена в обычные пользовательские ответы не добавляются.
Первый обработанный файл публикуется сразу; последующие версии — примерно каждые 5% файлов
(`INDEX_PUBLISH_PERCENT`). FAQ и ссылки обрабатываются после документов.
RAG проверяет новые версии каждые 3 секунды и загружает их в фоне; первая загрузка модели
может занять дополнительное время. Текущий запрос продолжает работать со своей версией.

Индексатор сохраняет файлы и батчи на диск. Повторная команда продолжает незавершённую работу;
готовые эмбеддинги переиспользуются. Изменение модели, точности или парсера требует пересчёта
соответствующих данных. Если индексатор уже работает, второй запуск не создаётся.
Режим `deploy` индексацию не запускает. Ошибки отдельных файлов сохраняют частичную базу,
но итоговая проверка не считает такой индекс полностью готовым.

## Что проверяет запуск

CI выполняет Ruff, pytest, проверку Compose и shell-скриптов, сборку образов и проверку импортов.
На VPS deploy ждёт healthcheck контейнеров, проверяет Redis и внутренний RAG API,
включая отказ при неверном токене. В режиме `index` он ждёт только анализа корпуса,
одного обработанного документа от каждого индексатора и доступности частичной базы.
Служебный бот `/index` показывает полный прогресс и проверяет итоговую публикацию;
после завершения присылает «Индексация завершена. База знаний полностью обновлена».

Полная индексация не ограничена длительностью Actions. Контейнер работает самостоятельно,
сохраняет прогресс и возобновляется после временной нехватки ресурсов.
Actions ждёт старт до 30 минут; сохранённая полностью готовая база переиспользуется сразу.

## Компоненты и настройки

| Компонент | Назначение |
| --- | --- |
| `service` | Статусы и уведомления администраторов в отдельном Telegram-боте |
| `bot` | Long polling, команды, форматирование, вызов RAG и история диалога |
| `rag` | FastAPI, FAQ, E5 + FAISS/BM25, RRF, rerank и генерация через Polza |
| `redis` | Последние 5 пар сообщений, TTL 24 часа, блокировка параллельного запроса |
| `indexer` | Парсинг DOCX/TXT/PDF, чанки, эмбеддинги и публикация версий индекса |
| Монитор VPS | Статусы Docker, свободные ресурсы, изменение лимитов индексатора |

По умолчанию: `intfloat/multilingual-e5-base`, CPU, динамическая INT8-квантизация,
общий батч 16, 2 потока модели, 2 процесса анализа и 3 параллельных рабочих индексатора
с общей моделью (`INDEX_WORKERS`); генератор — `qwen/qwen3.5-9b`.
Сначала анализируется весь корпус: форматы, объём, общее количество фрагментов, FAQ и ссылок.
Файлы всех форматов берутся из общей очереди от меньших к большим.
Общий процент учитывает объём текста и дополнительных записей, а не только число файлов.
Первая оценка использует `INDEX_ESTIMATED_CHUNKS_PER_SECOND` (по умолчанию 0.5 на рабочий
индексатор), число параллельных индексаторов и сохранённые векторы/батчи.
Документы оцениваются с учётом параллелизма, дополнительный этап FAQ/ссылок — отдельно.
Далее ETA использует суммарную выработку всех индексаторов за последние 60 секунд
общего реального времени. «Прошло» показывает только текущий запуск; накопленное время
прежних запусков хранится отдельно и в пользовательский таймер не добавляется.
Лимиты CPU/RAM и параметры модели задаются в серверном `.env` по [.env.example](.env.example).
Монитор сохраняет резерв 1 CPU и 3 GiB RAM и выделяет индексатору до 80% остатка;
при нехватке RAM останавливает его с сохранением прогресса и автоматически возобновляет
обработку, когда ресурсы снова доступны.
Файловый кэш, который ядро может освободить, исключается из рабочей памяти при проверке
остановки. При кратковременной нехватке CPU индексатор замедляется, а не перезапускается.
Причина остановки и значения памяти записываются в журнал монитора и сообщение служебного бота.

Команды основного бота: `/start`, `/reset`, `/index`, `/index_watch`, `/index_unwatch`.
Служебный бот: `/start`, `/status`, `/index` (`/progress`), `/requests` (`/stats`),
кнопки прогресса, статистики и подписок. `/requests` показывает число авторизованных
запросов к `/answer` за 1/5/30 минут и за всё время, обработанные запросы и ошибки;
счётчики сохраняются после перезапуска. Внешние HTTP-порты не публикуются.

Проверки выполняются на Ubuntu в GitHub Actions; локальный запуск кода не нужен.
Команды ниже выполняет CI:

```bash
uv sync --frozen --extra bot --python 3.12
uv run --frozen --extra bot ruff check .
uv run --frozen --extra bot ruff format --check .
uv run --frozen --extra bot pytest -q
```
